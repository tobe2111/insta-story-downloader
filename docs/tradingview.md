# 트레이딩뷰(TradingView) 연동 가이드

> 🇬🇧 English: [tradingview.en.md](tradingview.en.md)

트레이딩뷰의 **Pine Script 전략**에서 낸 알림(alert)을 이 프로그램이 받아,
검증된 실행 계층(리스크 사이징·데드밴드·장 시간 가드·체결 확인·킬스위치)을
그대로 태워 주문을 냅니다.

> ⚠️ **먼저 읽으세요.** 이 기능은 인터넷에 '주문을 실행하는 문'을 엽니다 —
> 이 시스템에서 가장 위험합니다. 반드시 페이퍼 모드로 충분히 검증하고,
> 아래 보안 설정을 모두 갖춘 뒤에만 실거래로 전환하세요. 이 프로그램은
> 수익을 보장하지 않습니다.

## 준비물

- **트레이딩뷰 유료 플랜** — 웹훅(webhook) 알림은 Pro 이상 기능입니다.
- **공개 URL** — 트레이딩뷰가 내 서버에 접속할 수 있어야 합니다. 집 PC라면
  포트포워딩이나 터널(cloudflared 등)이 필요하고, **HTTPS 리버스 프록시 뒤에
  두는 것을 강력히 권장**합니다(평문 HTTP로 비밀키가 오가면 안 됩니다).
- **긴 무작위 비밀키** — 아래 `QUANT_WEBHOOK_SECRET`.

## 1. 서버 실행 (먼저 페이퍼로)

```bash
export QUANT_WEBHOOK_SECRET='아주-길고-무작위인-문자열'   # 절대 공유·커밋 금지
python -m quant webhook --market crypto --symbols BTC/USDT --tradingview-ips
```

- `--tradingview-ips` : 트레이딩뷰 공식 발신 IP만 허용(권장). ⚠️ IP는 바뀔 수
  있으니 [트레이딩뷰 문서](https://www.tradingview.com/support/solutions/43000529348/)에서
  최신 목록을 확인하고, 다르면 `--allow-ips 1.2.3.4,5.6.7.8`로 지정하세요.
  리버스 프록시 뒤라면(발신 IP가 프록시로 보임) IP 옵션을 생략합니다.
- `--symbols` : 허용 종목 화이트리스트. 지정하면 그 종목 외 신호는 거부합니다.
- 실거래는 `--live` 추가(확인 프롬프트 + 실제 자금). 주식은 장 시간 가드가 자동 적용됩니다.

## 2. Pine Script 알림 설정

전략의 알림 메시지(Message)에 **JSON**을 넣습니다(반드시 본인 비밀키로):

```json
{"secret": "아주-길고-무작위인-문자열", "action": "{{strategy.order.action}}", "symbol": "BTC/USDT", "price": {{close}}}
```

- `action` : `long`/`buy`, `short`/`sell`, `flat`/`close`/`exit` 중 하나.
  Pine의 `{{strategy.order.action}}`은 buy/sell을 보내주며, 청산은 별도 알림에
  `"action":"flat"`으로 보냅니다. 부분 비중은 `"weight": 0.5`처럼 추가.
- `price` : `{{close}}`를 넣으면 네트워크 조회 없이 즉시 체결가 기준으로 실행됩니다.
- 알림의 **Webhook URL**에 내 서버 주소(`https://내도메인/`)를 넣습니다.

## 3. 동작 방식과 안전장치

- **멱등(idempotent)** : `action`은 '목표 비중'으로 해석됩니다. 같은 `long`을
  두 번 받아도 포지션을 같은 목표로 맞출 뿐 두 배로 사지 않습니다(데드밴드가
  잔조정도 걸러냄).
- **보안 5중** : ① 비밀키 상수시간 비교 ② IP 허용목록 ③ 재전송(replay) 중복
  차단 ④ (선택) 타임스탬프 신선도 ⑤ 본문 크기 제한. 비밀키가 없으면 서버가
  아예 뜨지 않습니다.
- **기존 실행 계층 재사용** : 리스크 사이징·시장충격·킬스위치·장 시간·체결
  확인이 그대로 적용됩니다. 웹훅은 '무엇을'만 정하고 '어떻게 안전하게'는
  기존 코드가 담당합니다.

## 정직한 한계

- 트레이딩뷰는 **개인용 시세/주문 API가 없습니다.** 이 연동은 트레이딩뷰의
  '신호를 받는' 것이지 데이터를 가져오는 게 아닙니다. 백테스트·검증은 여전히
  이 프로그램의 데이터(ccxt/yfinance)로 합니다.
- 웹훅 수신·주문 매핑은 테스트로 검증됐지만, **본인 환경(공개 URL·프록시·
  실계좌)에서의 종단 검증은 반드시 페이퍼로 먼저** 하세요.
- 트레이딩뷰 신호의 품질(수익성)은 전적으로 본인의 Pine Script 전략에 달려
  있습니다. 이 프로그램은 그 신호를 안전하게 집행할 뿐, 좋게 만들지 않습니다.
