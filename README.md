# Quant — 주식·코인 퀀트 자동투자 시스템

![CI](https://github.com/tobe2111/insta-story-downloader/actions/workflows/ci.yml/badge.svg)

Python 기반의 **퀀트 트레이딩 프레임워크**입니다. 코인(암호화폐), 국내주식,
미국주식을 대상으로 **전략 백테스팅 → 페이퍼 트레이딩 → 실거래**를 단계적으로
검증하며 진행할 수 있도록 설계되었습니다.

## ⚠️ 먼저 반드시 읽어주세요 (Disclaimer)

- **이 시스템은 "무조건 수익"을 보장하지 않습니다. 세상에 그런 시스템은 없습니다.**
  수익을 100% 보장한다고 광고하는 모든 자동매매 봇은 사기이거나 과최적화된
  결과일 뿐입니다.
- 퀀트 투자에서 장기적으로 살아남는 핵심은 "마법의 예측"이 아니라
  **철저한 리스크 관리와 반복 검증**입니다.
- 이 코드는 **교육 및 연구 목적**이며, 실제 투자 손실에 대한 책임은
  전적으로 사용자 본인에게 있습니다.
- 실거래 전에 반드시 **백테스트 → 페이퍼 트레이딩** 순서로 충분히 검증하세요.
- **생존 편향(survivorship bias)을 기억하세요.** 지금 데이터를 받을 수 있는
  종목은 '살아남은' 종목뿐입니다. 그동안 상장폐지·붕괴로 사라진 종목은
  백테스트에 아예 등장하지 않으므로, 현존 종목만으로 한 백테스트는 성과를
  체계적으로 **과대평가**합니다. 특히 종목 스크리닝·포트폴리오 백테스트가
  좋아 보일 때, 그 일부는 이 편향 때문일 수 있다고 가정하는 것이 정직합니다.

## 🚀 가장 간편한 시작

### 방법 1 — 무설치 실행파일 (가장 쉬움, 파이썬 불필요)

**아무것도 설치할 필요 없습니다.** 실행파일을 받아 더블클릭만 하세요:

1. **[Releases 페이지](https://github.com/tobe2111/insta-story-downloader/releases/latest)**
   에서 본인 OS용 zip 다운로드 (버튼 클릭 한 번):
   - Windows: `quant-cockpit-windows.zip`
   - macOS: `quant-cockpit-macos.zip` · Linux: `quant-cockpit-linux.zip`
2. 압축을 풀고 **`quant-cockpit` 실행파일을 더블클릭**
3. 브라우저에 조종석이 자동으로 열립니다 → 클릭으로 사용

> 다운로드 랜딩 페이지(`docs/`)를 무료로 공개하는 두 방법:
> - **Cloudflare (권장, 영구 무료)**: 저장소를 Cloudflare Workers & Pages에
>   연결하면 `wrangler.jsonc`(정적 에셋 전용, 빌드 없음)를 읽어 `docs/`를
>   그대로 서빙합니다. `main`에 push할 때마다 자동 재배포됩니다.
>   ⚠️ Cloudflare 프로젝트 설정에서 **Build command는 비워두세요**(정적이라 빌드 불필요).
> - **GitHub Pages**: Settings → Pages → Source를 `main`의 `/docs` 폴더로 →
>   `https://<계정>.github.io/<저장소>/` 로 공개.
>
> **릴리스 만들기 — 세 가지 방법**
> 1. **[자동/권장]** 루트의 `VERSION` 파일을 새 버전으로 바꿔 `main`에 머지하면,
>    그 값으로 태그·릴리스가 **클릭 없이 자동 빌드**됩니다(예: `VERSION`을
>    `v0.2.3`으로 커밋 → v0.2.3 릴리스 생성). ~5분 후 Releases에 OS별 파일 첨부.
> 2. Actions 탭 → "Build App" → Run workflow → 버전 입력 → 실행 (수동).
> 3. `v*` 태그 push.
>
> Windows는 원본 `.exe`(압축 해제 불필요), macOS·Linux는 zip으로 첨부됩니다.

> ⚠️ 윈도우/맥이 "알 수 없는 개발자" 경고를 낼 수 있어요(서명 안 된 개인 빌드).
> 본인이 빌드한 파일이니 "실행 허용"을 누르면 됩니다.

### 방법 2 — 더블클릭 실행기 (파이썬만 설치돼 있을 때)

- **윈도우**: `start.bat` 더블클릭
- **맥 / 리눅스**: `start.sh` 실행 (또는 `python3 start.py`)

필요한 라이브러리를 (처음 한 번) **자동 설치**하고, 웹 조종석을 켠 뒤
**브라우저를 자동으로 엽니다**. 그다음은 화면에서 클릭만 하면 됩니다.

> 이미 설치돼 있다면 `python -m quant web --open` 도 같은 효과(브라우저 자동 열기)입니다.

### 설치 후 업데이트 (최신 버전 받기)

설치한 뒤에는 자동으로 갱신되지 않습니다. 내 PC의 코드는 받은 그 시점 그대로 유지되며,
최신 버전을 쓰려면 한 번 받아와야 합니다.

- **윈도우**: `update.bat` 더블클릭
- **맥 / 리눅스**: `update.sh` 실행 (또는 `python3 update.py`)

최신 코드를 내려받고(`git` 설치본일 때), 새로 필요해진 라이브러리를 맞춰 설치한 뒤
무엇이 바뀌었는지 알려줍니다. 실행파일(방법 1) 사용자는 새 실행파일을 다시 받아
덮어쓰면 됩니다. `data_cache`·상태 파일 같은 결과물은 건드리지 않습니다.

> ⚠️ 업데이트는 '코드'만 최신으로 맞춥니다 — 수익을 높여주지 않습니다.
> 방향 예측 정확도 천장(대개 52~55%)은 어떤 업데이트로도 뚫리지 않습니다.

### 라이선스 키 (단건 판매용, 선택)

프로그램을 **단건(1회 구매)**으로 판매할 때 쓰는 경량 정품 확인 장치입니다.
**영구 키**(만료·구독·원격차단 없음)라 한 번 구매하면 계속 유효합니다.

- **판매자**: 강한 비밀을 정해 보관하고(`export QUANT_LICENSE_SECRET='…'`),
  구매자마다 키 발급 → `python -m quant.licensing gen --owner buyer@email.com`
  배포본은 `quant/_license_key.py`(깃 미포함)에 비밀을 넣고 `QUANT_REQUIRE_LICENSE=1`로 빌드
- **구매자**: 프로그램 폴더에 `license.key` 생성 →
  ```
  owner: buyer@email.com
  key:   QUANT-XXXXXX-XXXXXX-XXXXXX-XXXXXX
  ```
  (`QUANT_REQUIRE_LICENSE`가 꺼진 개발/직접 실행 시엔 키가 필요 없습니다.)

> ⚠️ **정직한 한계**: 배포된 코드/실행파일에는 검증 비밀이 함께 담기므로, 마음먹은
> 사람은 우회할 수 있습니다. 이건 완전한 복제방지(DRM)가 아니라 '정품 확인 + 캐주얼
> 공유 억제'입니다. **구독·만료 게이팅은 의도적으로 넣지 않았습니다** — 미등록 유료
> 자동투자 서비스는 국내 자본시장법상 위법 소지가 큽니다. 판매 전 반드시 핀테크
> 변호사에게 '유사투자자문업 신고' 필요 여부를 확인하고, **'수익 보장' 문구는
> 절대 쓰지 마세요**(사기죄). 도구(백테스트/리서치) 판매로 포지셔닝하세요.

## 설계 철학

```
데이터 → 전략(신호) → 리스크관리(사이징/손절) → 백테스트/실행 → 성과분석
```

1. **데이터 계층** (`quant/data`) — 코인/미국/국내 데이터를 동일한 인터페이스로 제공.
   네트워크가 없으면 합성 데이터로 자동 폴백하여 오프라인에서도 검증 가능.
2. **전략 계층** (`quant/strategies`) — 모멘텀, 이동평균 교차, 평균회귀 등.
   전략은 "목표 포지션 비중(-1.0 ~ 1.0)"만 계산합니다.
3. **리스크 계층** (`quant/risk`) — 포지션 사이징, 손절/익절, 최대 낙폭 제한.
   **여기가 실제로 돈을 지키는 가장 중요한 부분입니다.**
4. **백테스트 계층** (`quant/backtest`) — 수수료·슬리피지 반영, 룩어헤드 편향 방지.
   샤프지수, MDD, 승률 등 성과 지표 산출.
5. **브로커/실행 계층** (`quant/broker`, `quant/live`) — 페이퍼 트레이딩과
   실거래(ccxt 등)를 동일한 인터페이스로 연결.

## 통합 CLI (권장)

하나의 명령으로 주요 기능을 실행합니다:

```bash
python -m quant backtest --strategy ma_cross --report results/r.html
python -m quant validate --strategy ma_cross                 # 과최적화 검증 3종(아래 참고)
python -m quant sweep --market crypto --symbol BTC/USDT      # 민감도 히트맵
python -m quant web --port 8000                              # 로컬 웹 UI
python -m quant pipeline                                     # 백테스트+리포트+몬테카를로
python -m quant --help                                       # 전체 명령 보기
```

백테스트에는 회전율(비용) 절감 옵션이 있습니다 — 예측 개선이 아니라 미세 조정
거래의 왕복비용을 아끼는 **확정적 비용 수학**입니다:

```bash
python -m quant backtest --strategy ml --rebalance-band 0.03 --stop-cooldown 5
```

## 과최적화 검증 3종 — "이 전략을 믿어도 되는가"

**전략을 실전(페이퍼 포함)에 올리기 전 반드시 이 순서로 검증하세요.**
셋 다 '수익을 올리는' 도구가 아니라 '그럴듯한 거짓말을 걸러내는' 도구입니다.

```bash
python -m quant validate --market crypto --symbol BTC/USDT --strategy ma_cross
```

| 단계 | 도구 | 보는 것 | 통과 기준(관례) |
|---|---|---|---|
| 1 | 워크포워드 + **DSR** | OOS 성과 + 다중검정 보정 샤프 신뢰도 | DSR ≥ 0.95 |
| 2 | **PBO** | IS 1등 파라미터가 OOS에서 동전던지기인지 | PBO < 0.2 |
| 3 | **CPCV** | 여러 OOS 경로에서 성과가 일관되는지 | 최소 경로 샤프 > 0 |

> 세 검증을 모두 통과해도 **미래 수익은 보장되지 않습니다.** 통과는 "선택
> 절차가 노이즈를 고르고 있지 않다"는 뜻일 뿐입니다. 다음 단계는 페이퍼
> 트레이딩(`learn.bat`)으로 실데이터 검증입니다. 반대로 하나라도 크게
> 실패하면 그 전략/파라미터는 실전에 올리지 마세요.

### 자동 운용에서는 이 검증이 **비중에 직접 반영**됩니다 (검증 게이트)

매일 밤 전 종목(`quant.markets.AUTO_TARGETS`)을 다시 재고, 그 결과를
다음날 **통합 분산 계좌**의 목표 비중에 곱합니다. 킬스위치·변동성 타깃
**뒤에** 걸리므로 스케일러가 되돌려 키우지 못합니다.

> **어느 계좌에 걸리나 — 정확히.** 배치는 계좌 두 종류를 돌립니다.
> · **통합 분산 계좌**(`run_daily_portfolio`, 공개 챌린지) — 실제로 돈이
>   도는 쪽. **게이트가 걸립니다.**
> · **종목별 참고 계좌**(`run_daily_paper`) — 그 전략이 그 종목에서 어떻게
>   행동하는지 **재는 계기**. 게이트를 **일부러 안 겁니다.**
>
> 계기에도 게이트를 걸면 순환이 됩니다: 깎인 수익이 장부에 쌓이고, 그
> 장부에서 뽑은 켈리 상한이 다시 통합 계좌의 비중을 정합니다. 계기를 그
> 계기가 재는 대상으로 감쇠시키면 "이 전략이 원래 어떻게 행동하는가"를
> 영영 알 수 없게 됩니다. 그래서 사이트의 종목별 화면은 감쇠 전 값입니다.

| 등급 | 조건 | 비중 |
|---|---|---|
| 통과 | PBO ≤ 0.2 **그리고** DSR ≥ 0.95 **그리고** CPCV 최악 경로 > 0 | ×1.00 |
| 경고 | 그 사이 · **셋 중 하나라도 측정 안 됨** | ×0.50 |
| 실패 | PBO > 0.7 (관례상 "버릴 것") | ×0.00 (그날 관망) |
| 미측정·만료 | 기록 없음 / 날짜 없음 / 7일 초과 | ×0.50 |

> ⚠️ **미측정은 통과가 아닙니다.** "안 재봤다"와 "재봤더니 괜찮다"를 같게
> 취급하면 검증이 통째로 죽은 날 시스템이 가장 공격적으로 굴리게 됩니다.
>
> ⚠️ 왜 '전부 아니면 전무'가 아닌가 — PBO·DSR은 합격/불합격 도장이 아니라
> 연속적인 신뢰도 지표이고, 표본이 적으면 크게 흔들립니다. 이분법으로 끊으면
> '측정 잡음이 계좌를 끄는' 장치가 됩니다. 그래서 신뢰도를 비중으로 번역합니다.
>
> ⚠️ **반쪽 측정도 통과가 아닙니다.** PBO만 재고 DSR을 못 잰 기록은 흔한데
> (워크포워드가 DSR을 못 내면 null), 그런 기록이 만점을 받으면 위의 원칙이
> 필드 단위에서 무너집니다. 날짜가 없어 신선도를 확인할 수 없는 기록도 같습니다.
>
> ⚠️ **CPCV는 2026-08-14까지 계산되고 화면에 찍힌 뒤 버려졌습니다.**
> "3중 관문"이라 부르면서 셋째는 장부에 저장조차 되지 않아 어떤 판단에도
> 닿지 않았습니다. 지금은 저장되고 게이트에 들어갑니다.
>
> ⚠️ 2026-08-14 이전에는 이 검증이 **경보만 울리고 아무것도 막지 않았습니다.**
> 그동안 문서는 "통과한 전략만 씁니다"라고 말하고 있었고, 실제로는 PBO 0.78
> 짜리 종목이 매일 그대로 굴러갔습니다. 구현: `quant/live/validation_gate.py`

## 야간 자동 재학습 — 챔피언/챌린저 (이길 때만 교체)

매일 밤(GitHub Actions, 새벽 5시 KST) 최신 실데이터로 ML 후보들을 학습시켜
현재 챔피언 설정과 **2단계 검증**으로 대결시킵니다:

1. **선발전** (과거 구간): 모든 후보 vs 챔피언 — t-통계 임계를 넘는 최고 후보 선발
2. **결승전** (선발전이 못 본 최근 구간): 선발된 1명만 재검증 — 여기서도 이겨야 승격

도전자는 **고정 후보(ML 변형 + 전통 전략) + 챔피언의 돌연변이**(매일 밤 현재
챔피언 설정을 조금씩 변형해 새로 생성)로 구성됩니다 — 이긴 변형이 다음 날의
챔피언이 되고 그 주변을 다시 탐색하는 **언덕오르기식 진화**라, 후보 목록 밖의
설정도 시간이 지나며 탐색됩니다. 승격 관문은 동일하므로 탐색이 넓어져도
과최적화 방어선은 약해지지 않습니다.

결정 기록은 `state/champions.json` · `state/retrain_history.jsonl`에 자동
커밋되고, 웹 조종석 **감시** 탭에 현황 카드가 뜹니다. 수동 실행:

```bash
python -m quant retrain --market crypto --symbol BTC/USDT
```

**챔피언은 실제로 사용됩니다** — 페이퍼 학습(`learn.bat` / `python -m quant
learn`)의 기본 전략이 `champion`이라, 야간 재학습이 챔피언을 교체하면 실행
중인 봇도 **재시작 없이** 다음 사이클부터 새 챔피언으로 갈아탑니다. 웹
백테스트 폼에서도 전략 `champion`을 골라 현재 챔피언을 검증할 수 있고,
`examples/run_live.py --strategy champion` 으로 실전 추종도 가능합니다.
(승격 기록은 저장소의 `state/`에 쌓이므로, 내 PC 봇이 새 챔피언을 받으려면
`update.bat`으로 한 번 받아오세요 — 기록이 없으면 기본 챔피언(ml logreg)으로
동작합니다.)

> ⚠️ **재학습은 성공률을 계속 올리는 장치가 아닙니다.** 방향 예측 정확도의
> 현실적 상한은 대개 52~55%이며, 이 루프의 목적은 모델이 시장 변화에
> 뒤처지지 않게 하고 **검증을 통과한 개선만** 반영하는 것입니다. 챔피언이
> 오래 안 바뀌는 것은 고장이 아니라 정상입니다.

### 긴 검증 — 학습창은 그대로, 검증 구간만 길게

```bash
python -m quant walkforward                 # 최장 과거(기본 2,500봉 ≈ 주식 10년)
python -m quant walkforward --offline       # 네트워크 없이 저장된 스냅샷만
```

오늘의 챔피언 설정을 **훨씬 긴 과거**에 적용해 구간별로 몇 번 통했는지 셉니다.
`crosssection`(같은 설정이 **몇 종목**에서 통했나)을 옆이 아니라 **뒤로** 넓힌
같은 질문입니다. 매주 월요일 주간 워크플로가 자동으로 돌려 알림으로 보냅니다.

**학습창은 250봉 그대로입니다.** 10년치로 학습시키면 이미 죽은 패턴(2015년의
시장)을 배웁니다 — 늘리는 것은 검증 구간뿐입니다.

> ⚠️ **생존 편향** — 이 성적은 *오늘 살아남은* 종목으로만 계산합니다. 10년 전에는
> 이 20개를 고를 수 없었고, 그때 골랐을 종목 중 사라진 것들의 손실은 여기에
> 없습니다. **그래서 실제로 얻을 수 있었던 것보다 좋게 나옵니다.** 보고서가
> 이 문장을 항상 함께 싣고, 이 값은 승격 판정에 쓰지 않습니다(관찰 전용).

**대조군('그냥 보유')을 항상 함께 냅니다.** 플러스 비율만 보면 상승장에서는
저절로 높게 나옵니다 — 진짜 성적은 "들고만 있었을 때보다 나았나"입니다.

실측(2026-08-14 스냅샷, 오프라인, 20종목·125구간):

| | |
|---|---|
| 플러스 구간 | 78개 (62%) |
| **그냥 보유를 이긴 구간** | **39개 (31%)** |
| 구간 과반에서 보유를 이긴 종목 | 3 / 20 |
| 종목당 평균 노출 | 9% (종목별 참고 계좌 기준) |

예: SK하이닉스 전략 +21.6% vs 보유 +852.4%. **지금 이 설정은 장기 보유를
이기지 못합니다** — 그 사실을 숨기지 않고 매주 같은 표로 냅니다.

> ⚠️ 노출 9%는 **종목 하나만 굴리는 참고 계좌** 기준입니다. 20종목을 합친
> 통합 계좌의 총노출은 42~51%입니다(주간 보고서의 "굴린 자본"). 두 숫자를
> 뭉뚱그리면 "자본의 91%가 현금"이라는 틀린 결론이 나옵니다.

## 100만 챌린지 — 100만원 → 1억 (후원 매칭 입금)

통합 가상 계좌가 **100만원**으로 시작해 1억을 향해 갑니다.

> ### ⚠️ 먼저 정직한 숫자 — 지금은 '그냥 보유'보다 못합니다
>
> 2026-08-16에 세 가지 독립된 방법으로 재봤고 **전부 같은 답**이 나왔습니다.
>
> | 재는 방법 | 결과 |
> |---|---|
> | 긴 검증(구간별) | 125구간 중 '그냥 보유'를 이긴 것 **39개(31%)** |
> | 야간 오디션 | SPY·QQQ에서 이긴 전략이 **`buy_hold`(그냥 보유)** |
> | 횡단면 증거 | 20종목 중 19종목이 **같은 챔피언** — 사실상 실험 1개 |
>
> 예: SK하이닉스는 전략 **+21.6%** vs 그냥 보유 **+852.4%**.
>
> **그리고 1억은 100배입니다.** 지금 실측(샤프 ~0.5·노출 45%)이면 연 한 자릿수
> 수익률이고, 그 속도로 100배는 **수십 년**입니다. 이건 버그가 아니라 산수입니다.
>
> 그래서 이 저장소가 지금 증명하려는 것은 "1억"이 아니라 **"그냥 보유보다 낫다"**
> 입니다. 그게 먼저 증명돼야 나머지가 의미를 갖습니다. 못 하고 있으면
> 못 하고 있다고 이 표에 그대로 적습니다.

> 원래 이름은 '8마일 챌린지'였습니다(8종목 × 만원 = 8만원, 영화 8 Mile 오마주).
> 유니버스가 20종목이 되고 원금이 100만원이 되면서 그 이름이 아무것도 설명하지
> 못하게 돼 2026-08-14에 바꿨습니다. **그 이름으로 나간 지난 기록·캡션은
> 고치지 않습니다** — 그때는 그 이름이었고, 과거를 고치지 않는 것이 먼저입니다. 개별 종목 계좌는 각자 만원으로 참고용 기록을 따로 쌓습니다.
방송 후원이 들어오면 **같은 금액만큼 통합 가상 계좌의 원금을 늘리는** 이벤트
구조입니다. ⚠️ **후원금 자체를 운용하지 않습니다**(대가·지분 없음) — 이 구조를
바꾸면(타인 자금 운용) 유사수신·무인가 집합투자 위험이 생깁니다.

- 입금 등록(가장 쉬움): 웹 조종석 → **입금** 탭 → 금액·메모 입력. 최초 1회
  GitHub 토큰 설정이 필요하며 화면에 안내가 나옵니다(`QUANT_GH_TOKEN`).
- 폰에서: GitHub 앱/웹 → Actions → **Deposit** → Run workflow → 금액·메모 입력.
  두 방법 모두 사이트·방송 화면에 자동 반영되고 배너가 뜹니다.
- CLI: `python -m quant deposit --amount 10000 --memo "슈퍼챗 ○○님"`
- 회계는 **원금과 운용 손익을 분리**합니다: 수익률은 원금 대비, 실력 지표는
  입금 효과를 제거한 시간가중 수익률(TWR). 차트에는 원금 계단선과 입금 ▲
  마커가 표시되어 "점프는 후원, 기울기는 실력"이 구분됩니다.
- 모든 입금은 장부(deposits)로 git에 공개 기록됩니다(조작 불가).

재학습 링에는 챔피언의 돌연변이·레짐 필터 변형과 함께 **이벤트 가드 변형**
(FOMC 등 예고된 거시 이벤트 창에서 관망)도 도전합니다 — 이벤트 달력은 몇 년 치가
미리 공개돼 재현·검증이 가능하므로, 2단계 검증을 통과할 때만 챔피언이 됩니다.

결과는 웹사이트의 **[자동 페이퍼 현황](docs/paper.html)** 페이지(`docs/paper.html`,
사이트 자동 배포)에 매일 갱신됩니다 — 브라우저로 열어보기만 하면 됩니다.

## 실전 반영 — 진화하는 챔피언으로 실제 계좌 운용 (수동 스위치)

야간 재학습이 키운 챔피언을 실제 계좌에 반영하는 명령입니다. **자동으로 켜지지
않습니다** — 사람이 직접 실행하고, 실행 중에도 `실전` 두 글자를 타이핑해야
시작됩니다.

```bash
python -m quant setup                 # ① 거래소/증권사 API 키 저장 (.env, 최초 1회)
python -m quant live                  # ② 먼저 페이퍼로 챔피언 추종을 관찰 (기본)
python -m quant live --real           # ③ 실전 — 소액으로!
```

- **챔피언 자동 추종**: 야간 재학습이 챔피언을 교체하면 재시작 없이 다음
  사이클부터 새 전략이 적용됩니다 — 진화가 실전으로 이어집니다.
- **다중 종목 분산**: `--symbols "BTC/USDT,ETH/USDT,SOL/USDT"` — 같은 시장의
  여러 종목을 한 계좌에서 역변동성 배분으로 운용하며, 종목마다 각자의
  챔피언을 따릅니다.
- **안전장치(기본 켜짐)**: 일일 손실 -3% 킬스위치 · 최대낙폭 -15% 서킷브레이커 ·
  최대 비중 50% · 주식 장시간 가드 · 주문 재시도/체결 확인. 한도는
  `--daily-max-loss` `--max-drawdown` `--max-weight`로 조절합니다.
- **장중 감시**(2026-08-15~): 손실 감시가 새벽 배치에서 하루 한 번만 돌던 것을
  15분마다 돌게 했습니다(`python -m quant guard`). 진짜 산출물은 감시 자체가
  아니라 **"실제로 얼마나 자주 봤는가"의 실측 기록**입니다 — 설정한 주기가
  아니라 관측된 최악 간격이 위험 한도의 근거가 됩니다.
- **레버리지: 쓰지 않습니다**(총노출 상한 100%). 2026-08-15에 나중에 열기 위한
  관문 3종(강제청산 여유 · 장중 감시 실적 · 파산확률)을 먼저 세웠고, **셋을 다
  통과해야만** 열립니다. 기본값은 잠김이고 하나라도 모르면 잠깁니다.
  ⚠️ 영업 자료에 "레버리지 가능"이라고 쓰면 안 됩니다.
- 지원 시장: 코인(ccxt) · 미국주식(Alpaca) · 한국주식(한국투자/키움).
- 상태는 웹 조종석 **감시** 탭에서 실시간으로 볼 수 있습니다.

> ⚠️ 안전장치는 손실을 **보장하며 막아주지 못합니다**(갭·급변 위험). 잃어도
> 되는 소액으로만, 수개월의 페이퍼 검증 뒤에 시작하세요. 수익 보장은 없습니다.

### 100만 챌린지 실거래 전환 절차 (하루 1회 집행 — 준비 완료 상태)

3. **진단** — `python -m quant live-check --broker kis` (키→인증→잔고, 주문 없음).
   Actions에서는 `KR Live` 워크플로 수동 실행이 진단+모의투자 리허설까지 수행.
4. **모의투자 리허설** — `python -m quant live-daily` (기본이 모의투자).
   페이퍼 장부와 나란히 쌓여 슬리피지 차이가 데이터로 남는다.
5. **실전 전환(2중 잠금)** — `--real` 플래그 **그리고** 환경변수
   `QUANT_LIVE_REAL=1`(Actions는 Variables)이 둘 다 있어야 실탄이 나간다.
   자동 매일 실행은 `.github/workflows/kr-live.yml`의 schedule 주석 해제로.

> 전환 판단 기준(권장): 페이퍼 TWR가 랜덤 벤치마크 상위권 + 바이앤홀드 대비
> 초과성과를 90일 이상 유지할 때. 그 전의 실전은 통계가 아니라 도박입니다.

## 고급: 앙상블 · 레짐 필터 · 몬테카를로 검증

진짜 견고한 성과는 파라미터 최적화가 아니라 아래 3가지에서 나옵니다.

**① 전략 앙상블** — 상관이 낮은 전략을 결합해 자본곡선을 매끄럽게 만듭니다.
```python
from quant.strategies import StrategyEnsemble, MovingAverageCross, Breakout, RSIReversion
ens = StrategyEnsemble([MovingAverageCross(), Breakout(), RSIReversion()])
```

**② 레짐 필터** — 약세장/고변동성 구간에서 자동으로 관망해 대낙폭을 회피합니다.
```python
from quant.strategies import RegimeFilter
strat = RegimeFilter(ens, trend_window=200)   # 장기MA 아래면 매매 중단
```

**③ 몬테카를로 신뢰구간** — 샤프지수 하나에 속지 마세요. 수천 번 재추출해
"진짜 실력의 분포"를 봅니다. 하단(5%)이 0 근처면 그건 운입니다.
```python
from quant.robustness import bootstrap_metrics, summarize
print(summarize(bootstrap_metrics(result.returns)))
```

**통합 실행** — 백테스트 + HTML 리포트 + 몬테카를로를 한 번에:
```bash
python examples/run_config.py --config config/config.yaml
```

## 다중 종목 실시간 운용 + 알림 + 견고한 주문

여러 종목을 동시에 운용하며, 체결·오류를 텔레그램/슬랙으로 통지하고,
주문 실패 시 자동 재시도합니다.

```bash
python examples/run_multi.py --paper --market crypto \
    --symbols BTC/USDT ETH/USDT SOL/USDT --iters 3
```

- **알림** — 환경변수 설정 시 자동 활성화 (미설정 시 콘솔만):
  `TELEGRAM_BOT_TOKEN`+`TELEGRAM_CHAT_ID`, `SLACK_WEBHOOK_URL`,
  `DISCORD_WEBHOOK_URL` (디스코드: 채널 설정 → 연동 → 웹훅 만들기 → URL 복사.
  클라우드 자동 운용 알림도 같은 이름의 GitHub Secret을 등록하면 디스코드로 옵니다)
- **견고한 주문** — `RobustBroker`가 어떤 브로커든 감싸 지수 백오프 재시도 +
  최소수량/스텝 라운딩 + 실패 알림을 추가 (거래소 거절·레이트리밋 방어)

```python
from quant.broker import RobustBroker, get_broker
from quant.live import get_notifier
broker = RobustBroker(get_broker("crypto_live"), retries=3, backoff=2.0,
                      min_qty=0.0001, notifier=get_notifier())
```

(pandas 없이 표준 라이브러리만으로 렌더링).

### API 키 — 언제, 무엇이 필요한가

**백테스트·검증(validate)·페이퍼 트레이딩에는 키가 하나도 필요 없습니다.**
키는 ① 실거래 주문 ② 알림 ③ 보조 데이터(거시/재무)에만 필요합니다.

키 '발급'은 계좌 본인 인증 때문에 직접 하셔야 하지만, 발급 후에는 설정
마법사가 입력→저장(.env, git 미포함, 본인만 읽기 권한)→연결 확인까지
한 번에 끝냅니다:

```bash
python -m quant setup
```

이후 모든 명령이 `.env`를 자동으로 읽습니다(셸에서 직접 export한 값이 우선).
⚠️ 실거래 키는 거래소에서 **출금 권한을 반드시 꺼두세요.**

실거래 API 키 목록:

| 시장 | 환경변수 |
|------|----------|
| 코인 (ccxt 100+ 거래소: 업비트·빗썸·코인원·코빗·바이낸스·바이비트·OKX 등) | `EXCHANGE_API_KEY`, `EXCHANGE_SECRET`, (일부) `EXCHANGE_PASSWORD`, (선택) `EXCHANGE_QUOTE` |
| 미국주식 (Alpaca) | `ALPACA_API_KEY`, `ALPACA_SECRET` |
| 국내주식 (한국투자 KIS) | `KIS_APP_KEY`, `KIS_APP_SECRET`, `KIS_CANO`, `KIS_ACNT_PRDT_CD` |
| 국내주식 (키움, 베타) | `KIWOOM_APP_KEY`, `KIWOOM_SECRET`, `KIWOOM_ACCOUNT` |

> 코인 거래소는 `get_broker("crypto_live", exchange="upbit")` 처럼 거래소만 바꾸면 됩니다(업비트·빗썸은 KRW 기본). 국내주식은 **개인용 REST API가 있는 한국투자·키움만** 지원됩니다 — 대신·LS는 Windows COM 전용, 삼성·미래에셋·토스는 개인 API가 없어 연동이 불가능합니다.

### 주식 실거래의 안전장치 (그리고 정직한 한계)

주식은 코인과 달리 **① 정해진 시간에만 열리고 ② 시장가도 접수와 체결에 시차**가 있어, 그에 맞춘 장치를 두었습니다:
- **장 시간 가드**: 정규장(미국 09:30–16:00 ET / 한국 09:00–15:30 KST, 평일)이 아니면 주문을 내지 않습니다. `run_live.py --live --market us_stock`처럼 실거래+주식이면 자동 적용됩니다.
- **체결 확인**: 시장가 '접수'를 '체결'로 위조하지 않습니다. 접수 응답 후 **실제 포지션 변화를 폴링**해 진짜 체결 수량을 측정하고(추측성 조회 API를 늘리지 않고 검증된 잔고 조회만 사용), 시간 내 안 채워지면 미체결로 정직하게 보고합니다(재주문으로 이중 집행하지 않음).

> ⚠️ **정직한 한계 — 실계좌 전 반드시 확인하세요.** ① 위 장치와 브로커 파싱은 전부 목(mock) 테스트로 검증됐지만 **실제 거래소 API로는 아직 검증되지 않았습니다** — 응답 필드가 제 가정과 다르면 첫 실주문에서 어긋날 수 있습니다. **KIS·Alpaca가 무료 제공하는 모의투자 계좌로 소액 실주문을 먼저 넣어보세요.** ② 장 시간 가드에는 **공휴일 달력이 없습니다**(요일+시간만 판정) — 국경일·임시 휴장은 브로커 거부에 의존합니다. ③ 키움은 베타입니다.

## 나만의 전략 넣기 (커스텀 전략)

내 아이디어를 소스 수정 없이 꽂을 수 있습니다. `Strategy`를 상속해
`generate_signals(df)`가 목표 비중(-1~1)을 돌려주면 끝입니다.
`examples/custom_strategy.py`를 복사해 시작하세요.

```python
from quant.strategies.base import Strategy
class MyStrategy(Strategy):
    name = "my_strategy"
    def generate_signals(self, df):
        signal = ...                      # df로 목표비중 계산(미래 참조 금지)
        return self._finalize(signal, df.index)
```

이 파일을 **`strategies_user/` 폴더**에 넣으면 자동 등록되어, 기본 전략과 완전히
동등하게 쓸 수 있습니다 — 백테스트·**과최적화 검증(validate)**·페이퍼·실거래·웹
드롭다운 전부:

```bash
python -m quant backtest --strategy my_strategy
python -m quant validate --strategy my_strategy --grid '{"window":[20,50,100]}'
```

코드에서 직접 등록도 됩니다: `from quant.strategies import register_strategy`.
코딩이 부담되면 트레이딩뷰(Pine Script) 전략을 웹훅으로 받을 수도 있습니다.

> ⚠️ 커스텀 전략도 반드시 `validate`(과최적화 검증) → 페이퍼 순서로 확인하세요.
> `tests/test_leakage.py`가 미래 참조(룩어헤드)를 자동으로 잡아줍니다.

## 프로젝트 구조

```
quant/
├── data/         데이터 제공자 (crypto / us_stock / kr_stock / synthetic)
├── strategies/   전략 (MA/모멘텀/평균회귀/RSI/브레이크아웃/MACD/켈트너/스토캐스틱/ML/앙상블/레짐/ADX)
├── risk/         리스크 관리 (사이징, 손절, 익절)
├── backtest/     단일 종목 백테스트 엔진 + 성과 지표
├── portfolio/    다중 종목 포트폴리오 배분 + 백테스트
├── optimize/     그리드 서치 + 워크포워드 + 병렬 스윕/민감도
├── robustness/   몬테카를로 부트스트랩 (신뢰구간)
├── reporting/    HTML 리포트 + 라이브 대시보드 + 민감도 히트맵 (의존성 0)
├── broker/       주문 실행 (페이퍼 / ccxt / Alpaca / KIS / RobustBroker + 거래소규격)
├── live/         실시간 루프 (단일·다중 종목) + 알림(텔레그램/슬랙)
├── web/          로컬 웹서버 (http.server 기반, 브라우저에서 백테스트 실행)
└── utils/        로깅, HTTP 유틸
```
